# خطة التنفيذ المعتمدة: قياس خسارة الغلاء ونظام الدفعات عبر جدول المشتريات (purchases)

تطوير نظام قياس دقيق لـ **خسارة الغلاء الناتجة عن ارتفاع أسعار الشراء** وأثرها على الربح الفعلي لمحل البقالة في تونس، عبر **عدّاد تراكمي في لوحة التحكم** (يرصد الارتفاع منذ آخر جرد ويتصفّر عند كل جرد جديد)، و**بطاقة تحليلية بثلاثة أسطر مع جدول لأعلى 10 أصناف خسارة في تقرير الجرد**، بالاعتماد الحصري على جدول المشتريات `purchases` وسجلات الجرد السابقة دون إعادة هيكلة وثيقة المنتج، وبلا أي تعديل لأسعار البيع.

---

## مراجعة الضوابط والممنوعات الصارمة

> [!IMPORTANT]
> - **ممنوع قطعياً**: لا اقتراح لأسعار البيع، ولا أزرار لتعديل الأسعار (تحديد أسعار البيع متروك للسوق والتاجر).
> - **ممنوع قطعياً**: لا ديون، ولا معاملات تضخم تقديرية؛ الاعتماد حصراً على أسعار الشراء الفعلية للطبقات.
> - **التنسيق الإجباري**: جميع القيم المالية تُعرض بخط ثابت العرض (`font-mono tabular-nums`) وبثلاث خانات عشرية (`0.000 د.ت`).
> - **تنبيه الربح الحقيقي**: يظهر الرقم باللون الأحمر عند هبوطه إلى قيمة سالبة.

---

## 1. القواعد والمعادلات المعتمدة بدقة

### 1. الرصيد الافتتاحي في أول جرد بعد التنفيذ
- في **أول جرد بعد التنفيذ**: يُؤخذ الرصيد الافتتاحي لكل صنف من **آخر تقرير جرد محفوظ** في قاعدة البيانات، بالاعتماد على الحقلين المخزنين معاً:
  - `quantityAfter` (كمية الرصيد الافتتاحي).
  - `purchasePrice` (سعر شراء الرصيد الافتتاحي).
  *(ولا يُستخدم سعر المنتج الحالي، حيث تم التأكد أن التقارير السابقة تحفظ السعرين بالفعل)*.
- في **الجرد الثاني وما بعده**: تُستخدم مصفوفة الطبقات المتبقية (`remainingLayers`) المخزنة في التقرير السابق كرصيد افتتاحي دقيق متعدد الطبقات.

### 2. معادلة الكمية المباعة المعتمدة للصنف
$$\text{sold} = \text{quantityBefore} + \text{مشتريات الفترة} - \text{quantityAfter}$$
- `quantityBefore`: رصيد بداية المدة (من التقرير السابق).
- `مشتريات الفترة`: مجموع الكميات المشتراة للصنف خلال الفترة من جدول `purchases`.
- `quantityAfter`: المخزون الفعلي المحصور بالعدّ اليدوي أثناء الجرد الحالي.
- أي قيمة سالبة للكمية المباعة تُعلَّم كـ "خطأ عدّ" وتُستبعد من حساب خسارة الغلاء والإيراد.

### 3. تصفية مشتريات الفترة بالطابع الزمني الكامل (Full Timestamp)
- يُحدَّد تاريخ بداية الفترة الحالية بدقة عبر **الطابع الزمني الكامل لحفظ آخر جرد** (`lastJardTimestamp`).
- تُستعلم مشتريات الفترة من جدول `purchases` حيث:
  $$\text{purchase.date} > \text{lastJardTimestamp}$$
- يضمن هذا عدم فوات أو تكرار أي حركة شراء بالثانية والدقيقة.

### 4. قواعد العدّاد وعمليات التعديل والحذف
- **أول شراء لصنف لا سعر سابق له**: الأثر المحسوب على العدّاد يكون دائماً **صفر** (`impact = 0.000 د.ت`).
- **عند الشراء اللاحق لصنف بسعر أعلى بمقدار $\ge 0.010$ د.ت**:
  $$\text{impact} = \text{roundMoney}(\text{qtyAdded} \times (\text{newPrice} - \text{lastPrice}))$$
  يُخزن `priceHikeImpact: impact` داخل وثيقة الشراء، ويُضاف للعداد: `increment(impact)`.
- **عند تعديل حركة شراء**:
  يتم خصم الأثر القديم وإضافة الأثر الجديد في **نفس العملية الذرية (Batch Operation)**:
  $$\text{netImpactDelta} = \text{newImpact} - \text{oldImpact}$$
  `batch.update(counterRef, { currentAmount: increment(netImpactDelta) })`
- **عند حذف حركة شراء**:
  خصم القيمة المخزنة `purchase.priceHikeImpact`:
  `batch.update(counterRef, { currentAmount: increment(-purchase.priceHikeImpact) })`
- **عند حفظ الجرد**:
  أرشفة رصيد العدّاد في التقرير وتصفيره فورياً: `currentAmount: 0`.

## 2. بنية البيانات ومنع التكرار (Single Source of Truth)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        DATA AND LOGIC PIPELINE                         │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   [Purchases Collection (Single Source of Inflows)]                    │
│   ├── Filtered strictly by: timestamp > lastJardTimestamp              │
│   ├── Stores { priceHikeImpact: impact }                               │
│   └── Used to build FIFO Inflow Queue                                  │
│                                                                        │
│   [Last Saved Inventory Report]                                        │
│   └── Provides Opening Balance: quantityAfter & purchasePrice          │
│       (or remainingLayers for subsequent audits)                       │
│                                                                        │
│   [Inventory Audit Engine]                                             │
│   ├── sold = quantityBefore + periodPurchases - quantityAfter          │
│   ├── Consumes FIFO layers:                                            │
│   │   batchCost = cost of consumed layer                               │
│   │   latestCost = latest purchase cost in period                      │
│   │   itemLoss = sold * (latestCost - batchCost)                       │
│   │   bookProfit = revenue - (sold * batchCost)                        │
│   │   realProfit = bookProfit - itemLoss                               │
│   ├── Computes remainingLayers for next audit                          │
│   └── On Save:                                                         │
│       ├── Saves priceHikeSummary & remainingLayers in report           │
│       ├── Archives priceHikeSinceLastJard in report                    │
│       └── Resets counter: currentAmount = 0                            │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. تجربة المستخدم والتصميم البصري

### أ. لوحة التحكم: عدّاد "ارتفاع الأسعار منذ آخر جرد (تقريبي)"
- بطاقة مالية أنيقة برقم ثابت العرض وثلاث خانات عشرية (`font-mono tabular-nums`) تعرض مجموع الزيادات منذ آخر جرد.

### ب. شاشة تقرير الجرد: البطاقة التحليلية وجدول أعلى 10 أصناف
- **البطاقة العلوية**:
  - الربح الدفتري (`0.000 د.ت`).
  - خسارة الغلاء (`0.000 د.ت`).
  - الربح الحقيقي (`0.000 د.ت`، يُلوّن بالأحمر في السالب).
- **جدول أعلى 10 أصناف خسارة**:
  - الصنف، سعر الدفعة المباعة، سعر آخر دفعة، الكمية المباعة، وخسارة الغلاء الصافية.
  - وسم تحذيري واضح: `"مطابقة بالاسم، راجعه"` إذا لم يتوفر باركود.

## 4. الحالات الحدية (Edge Cases)

- **صنف بدفعة واحدة**: `latestCost = batchCost`، الخسارة = `0.000 د.ت`.
- **انخفاض سعر الشراء**: إذا وردت دفعة بسعر أقل، يُخصم الفارق من صافي مجموع الخسارة العام للجرد، وتُستثنى من جدول أعلى 10 أصناف.
- **كمية مباعة سالبة ($\text{sold} < 0$)**: تُعلّم كـ "خطأ عدّ" وتُستبعد من حساب الإيراد وخسارة الغلاء.
- **صنف لا سعر سابق له**: أثر الشراء الأول على العداد يساوي `0.000 د.ت`.

## 5. مصفوفة الاختبارات المعتمدة بالأرقام (Test Verification Matrix)

### الاختبار 1: صنف الـ 72 قطعة (الخسارة = 1.440 د.ت)
- **إعداد البيانات**:
  - رصيد بداية الجرد: 72 قطعة بسعر شراء `0.620 د.ت`.
  - وردت دفعة جديدة بسعر شراء `0.640 د.ت` (سعر آخر دفعة = `0.640 د.ت`).
  - بيعت الـ 72 قطعة بالكامل من الدفعة القديمة بسعر بيع `0.800 د.ت`.
- **النتائج المحسوبة**:
  - الإيراد = $72 \times 0.800 = \mathbf{57.600\text{ د.ت}}$.
  - تكلفة المباع = $72 \times 0.620 = \mathbf{44.640\text{ د.ت}}$.
  - الربح الدفتري = $57.600 - 44.640 = \mathbf{12.960\text{ د.ت}}$.
  - **خسارة الغلاء** = $72 \times (0.640 - 0.620) = 72 \times 0.020 = \mathbf{1.440\text{ د.ت}}$.
  - **الربح الحقيقي الصافي** = $12.960 - 1.440 = \mathbf{11.520\text{ د.ت}}$.

### الاختبار 2: صنف بثلاث دفعات متتالية (الخسارة = 31.000 د.ت، الربح الحقيقي = 7.000 د.ت)
- **إعداد البيانات**:
  - الدفعة 1: 50 قطعة بسعر `1.000 د.ت` (بيعت كلها 50).
  - الدفعة 2: 30 قطعة بسعر `1.200 د.ت` (بيع منها 20 وتبقت 10 قطع كـ `remainingLayers`).
  - الدفعة 3 (الأحدث): 40 قطعة بسعر `1.500 د.ت` (سعر آخر دفعة = `1.500 د.ت`).
  - سعر البيع الموحد: `1.600 د.ت`، إجمالي المباع = $50 + 20 = 70$ قطعة.
- **النتائج المحسوبة**:
  - الإيراد = $70 \times 1.600 = \mathbf{112.000\text{ د.ت}}$.
  - تكلفة الدفعات المباعة = $(50 \times 1.000) + (20 \times 1.200) = \mathbf{74.000\text{ د.ت}}$.
  - الربح الدفتري = $112.000 - 74.000 = \mathbf{38.000\text{ د.ت}}$.
  - **إجمالي خسارة الغلاء** = $25.000 + 6.000 = \mathbf{31.000\text{ د.ت}}$.
  - **الربح الحقيقي الصافي** = $38.000 - 31.000 = \mathbf{+7.000\text{ د.ت}}$.
  - الطبقات المتبقية للجرد التالي: 10 قطع بسعر `1.200 د.ت` و 40 قطعة بسعر `1.500 د.ت`.

### الاختبار 3: اختبار العدّاد الذري (تعديل، حذف، وتصفير)
- إضافة حركة شراء 50 قطعة بفارق `+0.050 د.ت` $\rightarrow$ زيادة العداد بـ $2.500$ د.ت.
- تعديل الكمية إلى 40 قطعة في نفس الحركة $\rightarrow$ خصم الأثر القديم وإضافة الجديد في نفس العملية ليصبح التأثير الصافي $2.000$ د.ت.
- حذف الحركة $\rightarrow$ خصم $2.000$ د.ت وعودة العداد فوراً.
- حفظ الجرد $\rightarrow$ تصفير العداد إلى `0.000 د.ت` وأرشفة القيمة في التقرير.

### الاختبار 4: صنف بوثيقتين منفصلتين (التحقق من عدم التكرار)
- التحقق من قراءة حركات التوريد حصرياً من `purchases` المصفاة بالطابع الزمني الكامل.
- النتيجة: منع أي تكرار مزدوج، وحساب الكمية المباعة بدقة متناهية.
